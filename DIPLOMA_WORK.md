# Что было реализовано в дипломном проекте

## Общее описание

Платформа **Surf Videos** — веб-приложение для совместного просмотра видео с Rutube в реальном времени.
Несколько пользователей заходят в одну комнату, видео у всех синхронизировано, есть чат и реакции.

**Стек:** React 19 + Vite (frontend), FastAPI + WebSockets (backend), MySQL, Redis, JWT-авторизация.

---

## Реализованный функционал

### 1. Авторизация
- Регистрация и вход через JWT-токены
- Хранение токена в localStorage (Zustand store)
- Защищённые роуты — незалогиненный пользователь перенаправляется на `/auth`
- При регистрации — обязательное согласие с Политикой персональных данных и Лицензионным соглашением (модальные окна с полным текстом)

### 2. Комнаты
- Создание публичных и приватных комнат
- Вход в приватную комнату по invite-коду (8 символов)
- Список публичных комнат в лобби
- Вкладка "Мои комнаты" — все комнаты, где состоит пользователь, включая приватные
- Возможность покинуть комнату (кроме владельца)
- Удаление комнаты владельцем или суперадмином

### 3. Синхронизированный плеер Rutube
- Видео загружается через официальный Rutube embed (iframe)
- Управление плеером через postMessage API (`player:play`, `player:pause`, `player:setCurrentTime`)
- Только владелец комнаты (admin) управляет плеером — остальные смотрят
- Состояние плеера (позиция, статус, video_id) хранится в Redis (TTL 24ч)
- Новый участник при входе получает актуальное состояние и синхронизируется
- Overlay "Нажмите чтобы начать просмотр" перед загрузкой iframe (autoplay policy браузера)

### 4. Синхронизация и компенсация рекламы
- Проблема: Rutube показывает рекламу каждому пользователю отдельно → рассинхрон
- Решение: admin каждые 5 секунд автоматически шлёт `sync`-событие с текущей позицией
- Зрители делают seek с поправкой на время доставки (`played_at`)
- Кнопка ручной синхронизации ⟳

### 5. Зал ожидания (синхронный старт)
- При смене видео все участники попадают в "зал ожидания"
- Каждый досматривает рекламу и нажимает "✓ Я готов"
- Владелец видит список готовых и запускает обратный отсчёт 3→2→1
- После 0 видео стартует у всех одновременно

### 6. Чат
- Сообщения в реальном времени через WebSocket
- История последних 50 сообщений при входе в комнату
- Аватарки пользователей в чате
- Логи действий (кто поставил на паузу, кто вошёл/вышел)

### 7. Реакции
- Кнопки реакций под плеером: ❤️ 😂 😮 👏 🔥 😢
- При клике — летящий эмодзи анимируется поверх видео (у всех участников)
- Реакции записываются в таймлайн (Redis), привязаны к позиции видео
- Таймлайн отображается точками над полосой прокрутки (с tooltip при наведении)

### 8. Очередь видео
- Вкладка "Очередь" в боковой панели
- Владелец добавляет/удаляет/пропускает видео
- При skip — плеер автоматически переключается на следующее видео
- Зрители видят очередь (только для чтения)

### 9. Модерация в комнате
- Вкладка "Участники" — список всех онлайн-пользователей
- Владелец комнаты может: замутить (🔇) и кикнуть (✕) любого участника
- Замученный видит уведомление вместо поля ввода чата
- Кикнутый возвращается в лобби (WebSocket закрывается с кодом 4011)
- Суперадмин имеет права модерации в любой комнате

### 10. Режим кинотеатра и полный экран
- Кнопка "Кинотеатр" — скрывает шапку, растягивает плеер, управление появляется поверх видео
- Кнопка "Полный экран" (Fullscreen API)
- В полноэкранном режиме — кнопка оверлея чата (💬), новые сообщения всплывают снизу-слева

### 11. Профиль пользователя
- Страница `/profile`: аватар, имя, статистика (комнат создано / посещено), дата регистрации
- Загрузка аватара: файл кропается в квадрат 128×128 через Canvas API, сохраняется как base64
- Смена пароля (требует старый пароль)
- Запрос на удаление аккаунта (см. ниже)

### 12. Тёмная / светлая тема
- Переключатель в шапке на всех страницах
- CSS-переменные (`--c-bg`, `--c-accent` и др.), переключаются через `data-theme` атрибут
- Выбор сохраняется в localStorage

### 13. Суперадмин и панель администратора
Суперадмин (`is_superuser = true`) — системный пользователь, создаётся автоматически из `.env`.

**Вкладка "Панель администратора" в лобби (видна только суперадмину):**
- Статистика: пользователей / комнат / администраторов / онлайн сейчас (живой счётчик)
- Таблица пользователей: поиск, бейджи ролей, кнопки "Назначить/Разжаловать", "Бан/Разбан", "Удалить"
- Таблица комнат: поиск, онлайн-счётчик, кнопки "Войти" и "Удалить"
- **Запросы на удаление аккаунта** (тикеты): таблица с заявками пользователей, кнопки одобрить/отклонить

### 14. Запросы на удаление аккаунта (в соответствии с политикой персональных данных)
- В профиле пользователя: раздел "Удалить аккаунт" — форма с необязательной причиной
- Пользователь может отозвать ожидающую заявку
- Если заявка отклонена — можно подать повторно
- В панели суперадмина — вкладка "Запросы на удаление":
  - Список всех заявок (ожидающие идут первыми)
  - Одобрить → аккаунт удаляется со всеми данными
  - Отклонить → статус заявки меняется

## Архитектурные решения

### WebSocket протокол
Единственный WS endpoint: `GET /ws/rooms/{room_id}?token=...`
- Токен передаётся в query параметре (не в заголовке, т.к. браузерный WebSocket не поддерживает кастомные headers)
- Аутентификация до `ws.accept()`, отказ через коды 4001 / 4003 / 4004 / 4010 / 4011
- In-memory хранилище подключений: `dict[room_id → dict[user_id → WebSocket]]`
- `handlersRef` паттерн для предотвращения stale closure в React-хуке

### Redis
Ключи с TTL 24ч:
- `room:{id}:player` — текущее состояние плеера
- `room:{id}:queue` — очередь видео
- `room:{id}:video:{vid}:timeline` — таймлайн реакций
- `room:{id}:waiting` — флаг зала ожидания
- `room:{id}:ready_users` — список готовых пользователей
- `room:{id}:muted_users` — список замученных

### Защита от двойного монтирования React StrictMode
WebSocket хук использует `cancelled`-флаг и проверку состояния `CONNECTING` — предотвращает двойное подключение при double-mount в dev-режиме.

### NaN защита в плеере
Вся работа с позицией через `isFinite(Number(x)) ? Number(x) : 0` — защита от undefined/NaN при потере состояния.

## Файловая структура

```
backend/app/
  models/         — User, Room, RoomMember, Message, DeletionRequest
  schemas/        — Pydantic модели
  services/       — auth (JWT+bcrypt), deps (get_current_user)
  routers/        — auth, rooms, admin, users
  websocket/      — manager, router, handlers

frontend/src/
  pages/          — AuthPage, LobbyPage, RoomPage, ProfilePage
  hooks/          — useWebSocket
  player/         — RutubePlayerController, PostMessageBridge, CommandQueue
  store/          — auth (Zustand), theme (Zustand)
  api.js          — axios instance с Authorization interceptor
```
